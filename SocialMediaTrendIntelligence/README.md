# Cross-Platform Social Media Trend Intelligence & Prediction System

An MCA academic project demonstrating **Data Science** and **Deep Learning**
techniques on a cross-platform social-media trend dataset, delivered as a
local Flask web application.

> **This is an academic prototype, not a real-time social-media monitoring
> system.** It does not connect to Instagram, X, YouTube or TikTok APIs and
> does not scrape any website. All data is a statistically simulated CSV
> dataset created for this project.

---

## 1. Problem Statement

Brands, creators and researchers want to understand which kinds of posts
"trend" across platforms — but reasoning about virality by eyeballing raw
views/likes/comments/shares numbers is unreliable, because these metrics
scale very differently by platform and post type. This project builds a
**single, comparable Trend Score** from a post's engagement, growth and
reach, and then trains both a traditional Machine Learning model and a
Deep Learning model to predict a post's trend category (**Low / Moderate /
High**) directly from its raw metrics — without needing the derived score
at prediction time.

## 2. Objective

- Demonstrate a complete Data Science pipeline: cleaning, feature
  engineering, EDA, traditional ML modelling and evaluation.
- Demonstrate a complete Deep Learning pipeline: a Feed-Forward ANN built
  and evaluated with TensorFlow/Keras.
- Compare the two modelling paradigms on an identical train/test split and
  identical input features, so the comparison is fair.
- Package it all as a small, explainable web application suitable for a
  college viva — not a production system.

## 3. Features

- Cross-platform trend analysis with filters (platform, category, topic, date range)
- Engagement-rate and project-defined Trend Score computation
- Sentiment analysis (VADER)
- Data visualization (8+ charts across Dashboard and Trend Analysis pages)
- Data Science prediction (Logistic Regression baseline + Random Forest)
- Deep Learning prediction (Feed-Forward ANN / MLP)
- Side-by-side DS vs DL prediction on the same input
- Data-driven **Content Strategy** page (best day to post, top platform/category combinations, top topics, personalized recommendations) — a product-facing feature built on the same aggregated data
- SQLite-backed login and prediction history

## 5. Dataset

`dataset/social_media_trends.csv` — **8,040 records** (generated by
`utils/generate_dataset.py`), simulating posts across **Instagram, YouTube,
X and TikTok** in 8 categories. It is **not scraped or real data**; it is
statistically simulated so that views, likes, comments, shares, growth
rate and sentiment are meaningfully correlated (via a shared latent
"post quality" factor per record), giving the ML/DL models genuine
patterns to learn rather than noise. It also deliberately contains a
small amount of realistic messiness — missing values, duplicate rows and
a few extreme outliers — for the preprocessing pipeline to handle.

Columns: `post_id, platform, date, topic, category, views, likes, comments,
shares, growth_rate, sentiment, sentiment_score` (+ derived `engagement_rate,
trend_score, trend_label`).

## 6. Data Preprocessing

Implemented in `utils/preprocessing.py` (imported by both the notebooks and
the Flask app, so there is a single source of truth):

1. Duplicate removal (by `post_id`)
2. Data-type conversion (dates, numerics)
3. Missing-value imputation (median for `sentiment_score` / `growth_rate`;
   rows missing a critical identifier are dropped)
4. Outlier handling (views capped at the 99th percentile)
5. Categorical encoding (`LabelEncoder` for `platform`, `category`)
6. Numerical feature scaling (`StandardScaler`, fit on the training split only)
7. Feature selection (`trend_score` is excluded from the model's input
   features — it is *derived from* engagement/growth/views, so including it
   would leak the answer)
8. Train/test split (80/20, stratified by trend label)

## 7. Feature Engineering

**Engagement Rate**
```
Engagement Rate = ((Likes + Comments + Shares) / Views) × 100
```
Division by zero is handled safely.

**Trend Score** *(project-defined — not an official social-media metric)*
```
Trend Score = 0.4 × normalized(engagement_rate)
            + 0.3 × normalized(growth_rate)
            + 0.3 × normalized(views)
```
Each component is normalized using **percentile rank** (each value's rank
among all posts, scaled to [0,1]) rather than plain min-max. Raw
views/engagement are right-skewed with a long "viral" tail; min-max
normalization lets a handful of outliers compress nearly every other post
toward 0, producing a badly imbalanced Low/Moderate/High split.
Percentile-rank normalization is robust to that skew.

**Trend Label** thresholds on the resulting 0–100 score:
- Low: `< 40`
- Moderate: `40 – 70`
- High: `>= 70`

## 8. Data Science Methodology

Two classifiers predict `trend_label` from the 9 input features
(`platform, category, views, likes, comments, shares, growth_rate,
sentiment_score, engagement_rate`):

- **Logistic Regression** — baseline linear classifier
- **Random Forest** (200 trees, max depth 12) — main Data Science model,
  with feature importances

Both are trained in `utils/ml_model.py` / `notebooks/03_machine_learning.ipynb`
and saved with `joblib`.

## 9. Deep Learning Methodology

**Architecture** (`utils/dl_model.py` / `notebooks/04_deep_learning.ipynb`):
```
Input (9 features)
  → Dense(64, ReLU) → Dropout(0.3)
  → Dense(32, ReLU) → Dropout(0.2)
  → Dense(3, Softmax)          # Low / Moderate / High
```
- Loss: `sparse_categorical_crossentropy`
- Optimizer: `Adam`
- `EarlyStopping` on validation loss (patience 8, restores best weights)
- Trains in well under a minute on CPU — no GPU required

## 10. Evaluation Metrics

Both components are evaluated identically on the same held-out test set:
Accuracy, Precision (macro), Recall (macro), F1-score (macro), and a
Confusion Matrix. **All metrics are computed from the actual trained
models — nothing is hardcoded.** These evaluation artifacts (classification
reports, confusion matrices, feature importance, training curves) live in
`notebooks/03_machine_learning.ipynb` and `notebooks/04_deep_learning.ipynb`
rather than in the live web app: the app is designed to read like a real
product a user would actually use, and a product doesn't surface internal
model-evaluation statistics to its users. Example results from the
reference training run (yours may vary slightly by run):

| Model | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|
| Logistic Regression | ~96.6% | ~96.5% | ~96.3% | ~96.4% |
| Random Forest | ~98.3% | ~98.4% | ~98.3% | ~98.3% |
| Neural Network | ~98.7% | ~98.7% | ~98.7% | ~98.7% |

## 14. Limitations

- The dataset is synthetically generated, not collected from real
  platforms; absolute metric values are illustrative, not real-world
  benchmarks.
- Sentiment in the dataset is generated alongside the other fields rather
  than derived from real post captions (a working VADER-based analyzer is
  included in `utils/sentiment.py` for scoring free text).
- The Trend Score/Label is a project-defined formula, not an
  industry-standard metric.
- No authentication hardening (rate limiting, CSRF tokens, etc.) beyond
  what is appropriate for a local academic prototype.

## 15. Future Scope

- Replace the synthetic dataset with a real, licensed social-media dataset.
- Add time-series forecasting of trend score (e.g., for a specific topic).
- Add richer NLP-based sentiment analysis on actual post captions.
- Add per-user accounts and role-based access instead of a single demo login.
- Experiment with gradient-boosted trees (XGBoost/LightGBM) as an
  additional Data Science baseline.
